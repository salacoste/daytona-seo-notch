Playbooks · pick your scenario

Every stage of a site's life, covered

The same executable machinery, aimed at the right moment: before the first line of code, while pages are still being built on localhost, and after the site is live. Full manuals live in the repository (docs/manuals/); this page is the map.

1 · Brand-new site

Nothing exists yet — a new client or product. Start with understanding, end with a zero-decision launch.

/daytona-seo-notch-brief — intake

Structured client brief: business, audience, competitors, markets (Yandex vs Google priority for RU). Artifact: brief-<slug>/.

Queries + search volume

Seed pool → expansion → the agreement gate: a signed query table with volume per source (Google Keyword Planner, DataForSEO, Yandex Wordstat flow — no invented numbers).

/daytona-seo-notch-prelaunch Phase 0 — strategy

Site type (corporate / landing / blog) → IA and the URL map: every route gets its query, title draft and schema type. Sitemap is designed here.

Phases 1–2 — build with a gate

Template checks on the dev server; then the pre-launch gate: full audit of localhost/dist, sitemap generation, AI readiness, drift baseline, CI recipe for PRs.

Phase 3 — go-live switch

No decisions on launch day: remove noindex (verified), Search Console + Yandex Webmaster, analytics firing, first production audit, prod drift baseline, IndexNow.

2 · Site in development — something already exists

Half the pages are coded, some content is written. Mine what exists before asking anyone anything.

Step 1

Local scan

/daytona-seo-notch-brief Stage B: reads the project — identity docs, per-file content inventory (H1/title/meta/flags), SEO signals in code, stack verdict (SSR/SSG/SPA), native vocabulary → seed queries. Every fact cites its file.

Step 2

Brief the gaps, agree queries

Stage A asks only what the scan couldn't answer; then the query agreement gate and volume, same as the new-site path. Delta to the IA: which agreed queries lack a URL.

Steps 3–4

Gate & launch

Bring templates to standard, run the pre-launch gate on localhost (audit, sitemap, AI readiness, drift baseline), then the same zero-decision go-live switch. Replacing an old site? The 301 redirect map is a gate item.

The site is live. Understand it, connect real data, fix by priority, monitor forever.

Connect data
