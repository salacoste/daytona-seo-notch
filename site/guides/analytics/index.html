Guide · ~25 minutes · read-only

Feed your SEO agent real traffic data

Connect Google Analytics 4 and Yandex Metrika once — after that, audits and /daytona-seo-notch-analytics work with measured numbers: sessions, organic engine split, and the Yandex search phrases GA4 cannot show.

Step 0 — one local secrets file

git check-ignore .env.marketing || echo "add .env.* to .gitignore first"
(umask 077; set -C; : > .env.marketing)

Everything below goes into .env.marketing (0600, gitignored). Keys are never pasted into chat, logs or commits — CI scans for leaks.

Step 1 — Google Analytics 4

Two paths: a quick access token for reads, or full OAuth for permanent, refreshable access.

Quick · ~10 min

Access token + Property ID

Token: gcloud auth application-default print-access-token (or OAuth Playground, scope analytics.readonly). Property: Admin → Property Settings → numeric Property ID — not the G-… measurement ID.

GA4_ACCESS_TOKEN="ya29...."
GA4_PROPERTY_ID="123456789"

Test: node --env-file=.env.marketing tools/clis/ga4.js reports run --property 123456789 --metrics activeUsers --start-date 2026-10-21 --end-date 2026-10-28

Access tokens expire in ~1 hour — fine for exploration; use OAuth for regular work.

Full · OAuth runtime

Refreshable, audit-grade

Enable the Analytics Data API (and Search Console API) in Google Cloud, then:

cd tools/seo-runtime && uv sync --group google
tools/seo-runtime/run google_auth.py --setup
tools/seo-runtime/run google_auth.py --auth

Fastest for your own properties: gcloud auth application-default login --scopes=…webmasters.readonly,…analytics.readonly. Verify with google_auth.py --check.

Free bonus while you're in Google Cloud: create an API key restricted to PageSpeed Insights + CrUX and save as GOOGLE_API_KEY — unlocks field Core Web Vitals in every audit.

Step 2 — Yandex Metrika

Register an OAuth app

At oauth.yandex.ru — platform "Web services", redirect URI https://oauth.yandex.ru/verification_code, access: Yandex.Metrika → metrika:read (read-only).

Authorize and copy the token

Open https://oauth.yandex.ru/authorize?response_type=token&client_id=<CLIENT_ID> in the browser, allow access, copy access_token from the URL — locally only.

Save and find your counter

YANDEX_METRIKA_TOKEN="y0_AgAAAA..."
YANDEX_METRIKA_COUNTER_ID="12345678"   # optional default

First read

node --env-file=.env.marketing tools/clis/yandex-metrika.js counters list
node --env-file=.env.marketing tools/clis/yandex-metrika.js stats summary \
  --start 2026-10-01 --end 2026-10-28

Step 3 — verify the whole stack

In Antigravity, one command checks every configured source and builds the cross-engine snapshot.

overview

Period snapshot

Sessions, users, bounce and duration per engine — GA4, Metrika, plus GSC clicks when configured.

organic

Engine split

Metrika's source report shows organic.yandex vs organic.google — one query, the split GA4 can't give per visit.

phrases

Yandex queries

Real search phrases (ym:s:searchPhrase) — keyword research straight from your own traffic.

From then on, /daytona-seo-notch-audit enriches itself automatically whenever credentials are present. Full manual with troubleshooting: docs/CONNECT-ANALYTICS.md.
